## Choosing a model

Most people should not read the whole table. Three questions decide it.

**Do you need a specific model?** Some tasks have a known best answer. If a model family
or an exact id is required, check the table above — availability also depends on your plan.

**What is the task?**

- **Agent loops and long sessions.** Most input in an agent run is re-read context, so
  cache-read rate matters more than headline input price. A cheap model with a good
  cache rate often beats an expensive one over a long session.
- **Bulk work** where output dominates, such as batch generation or classification of a
  large corpus. Output is typically 3–4× the input rate, so compare output price first.
- **One-off or short requests.** A short request never amortises cache, so the raw input
  rate is the honest comparison.

**How fast?** Speed is published as tokens per second. Above roughly 50 tok/s the model
feels immediate; below roughly 15 tok/s, long answers visibly stall. A slower model is
often fine for background work and painful for anything interactive.

## Which models support which endpoint

Every model is reachable through the OpenAI-compatible route. Four also accept the
Anthropic Messages format, which is what Claude Code and other Anthropic-shaped clients
send.

| Endpoint | Path | Models |
| --- | --- | --- |
| Chat (all models) | `POST /v1/chat/completions` | all 40 |
| Anthropic Messages | `POST /v1/messages` | `claude-opus-5.5`, `gpt-6-astra`, `gpt-6-luna`, `gpt-6-sol` |
| SystemOne (decision) | `POST /v1/systemone` | `typesafe/jev` |

<Aside type="note" title="Only 7 models are on the default plan">
	Most models require a paid plan. The table dims any model your selected plan cannot
	reach, so you can see what exists before deciding which plan to buy. Switching plan in
	the table updates every price and which models are marked unavailable.
</Aside>

## How pricing is calculated

The charge is not the headline number. Two multipliers apply, and skipping either gives
you a price that does not match your bill.

**Step 1 — base rate per 1M tokens.** Derived from the model's published ratio:

```
base input  = 2 × model_ratio
base output = base input × completion_ratio
base cache  = base input × cache_ratio
```

**Step 2 — your plan's multiplier.** Every model is priced against the group it is
enabled in, and each group carries a discount:

| Plan | Multiplier | Example: a $2.50 base model |
| --- | --- | --- |
| Pro | ×0.45 | $1.12 |
| VIP | ×0.50 | $1.25 |
| Subscriber | ×0.60 | $1.50 |
| Default | ×0.70 | $1.75 |
| Vibecode | ×0.70 | $1.75 |

A model can sit in several groups at once. A model available on both Pro and VIP is
cheaper for you on Pro, so the table asks which plan you are on rather than guessing.

### Worked example

`deepseek/deepseek-v4-flash` has a base rate of **$0.22 / $0.66 / $0.066** per 1M input,
output and cache-read tokens. On the Pro plan (×0.45):

| | Base | On Pro (×0.45) |
| --- | --- | --- |
| Input | $0.22 | $0.099 |
| Output | $0.66 | $0.297 |
| Cache read | $0.066 | $0.0297 |

An agent turn that sends 10K fresh input, 2K cache-read and writes 1K output costs
`10000/1e6 × 0.099 + 2000/1e6 × 0.0297 + 1000/1e6 × 0.297`, which is about **$0.0013**.

The cache-read column is the one to watch in agent loops. On a long session the majority
of input tokens are re-read context billed at the cache rate, not the input rate, so the
real cost sits much closer to the cache figure than to the headline input price.

## Calling a model

The id in the table is the id you send, verbatim:

<Tabs>
	<TabItem label="Chat completions">
		```bash
		curl https://gurouter.com/v1/chat/completions \
		  -H "Authorization: Bearer <API_KEY>" \
		  -H "Content-Type: application/json" \
		  -d '{
		    "model": "deepseek/deepseek-v4-flash",
		    "messages": [{ "role": "user", "content": "Say hello in one sentence." }]
		  }'
		```
	</TabItem>
	<TabItem label="Anthropic Messages">
		Only the four models marked `anthropic` above. Used by Claude Code and other
		Anthropic-shaped clients.

		```bash
		curl https://gurouter.com/v1/messages \
		  -H "Authorization: Bearer <API_KEY>" \
		  -H "Content-Type: application/json" \
		  -H "anthropic-version: 2023-06-01" \
		  -d '{
		    "model": "claude-opus-5.5",
		    "max_tokens": 256,
		    "messages": [{ "role": "user", "content": "Say hello in one sentence." }]
		  }'
		```
	</TabItem>
	<TabItem label="SystemOne">
		A decision endpoint, not a chat. It does not stream and takes a different request
		shape. See the [SystemOne reference](/api/systemone/).

		```bash
		curl https://gurouter.com/v1/systemone \
		  -H "Authorization: Bearer <API_KEY>" \
		  -H "Content-Type: application/json" \
		  -d '{ "model": "typesafe/jev", "state": "…", "questions": { } }'
		```
	</TabItem>
</Tabs>

Confirm the exact ids your key can reach with [`GET /v1/models`](/api/openai-compat/). It
returns the same list at call time, including each model's `supported_endpoint_types`.

## Staying current

The table is a committed snapshot, regenerated from the live pricing API:

```bash
bun run sync:models
```

That keeps a docs build from depending on a third-party endpoint, and makes a price
change a reviewable diff rather than something that silently changes between one reader
and the next. Last synced
